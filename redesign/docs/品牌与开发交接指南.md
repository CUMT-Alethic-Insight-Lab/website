# Alethic 品牌与开发交接指南

适用对象为设计学生、前端开发与接手 Agent。新增内容时，先决定它属于首页叙事还是独立详情，再用一段真实内容、一个清楚的入口和一种能解释内容关系的图形完成首版。交付时附双语入口、静帧、键盘走查和同一构建的验收结果。

## 1. 站点结构和改动入口

公开官网由 Node 将模板、内容和公共资源构建成静态 `dist/`。首页 `/` 与 `/index.html` 使用同一份页面，英文在 `/en/`。全屏开场保留品牌字形和进入正文的链接，`#entry` 通向正文页眉。之后是原生滚动的十幕。桌面按吸顶栏下的可用高度安排一幕，内容长时继续向下排，窄屏按内容自然增长。公开展示的会议幕保留四阶段预览，完整示例在独立 `/meeting.html`。成员、技术文章、FLUED 总览及其四个子页也保留独立 URL。

| 任务 | 从哪里开始 |
| --- | --- |
| 新增、排序或改名首页幕 | `src/topic-routes.mjs` 管章节顺序、双语文案、主题文件名和公开片段。`src/story-template.mjs` 生成 `.story-screen`，`src/editorial.mjs` 提供多数正文。第一幕由 `src/lab-workbench.mjs` 单独生成。 |
| 新增真正的独立页面 | 在 `src/editorial.mjs` 或 FLUED 的 `src/flued.mjs` 注册页面，在 `src/page-template.mjs` 配置首屏主操作。`build.mjs` 负责双语、页眉、正式地址和构建产物。 |
| 调整菜单和锚点 | `build.mjs` 的 `siteNavigation` 管菜单入口，`src/story-template.mjs` 的 `oldTopic()`、`storyHref()` 管兼容与链接重写，`src/home-nav.mjs` 更新选中状态。 |
| 调整字符场、定位与切换 | `src/field.mjs`、`src/coordinates.mjs` 管开场和字格，`src/page-scene.mjs` 管正文图形及净区，`src/scroll-story.mjs` 管当前幕。`src/anchor-scroll.mjs` 与 `src/travel.mjs` 管页内到达与跨页反馈。 |
| 调整组件或主题 | 先查 `src/design-system.css` 和 `src/system.css`，再查 `src/controls.css`、`src/header.css`、`src/home-nav.css` 以及所在页面的 CSS。`src/entry.mjs` 接线语言、主题和运行模块。 |

当前顺序为 `#position` → `#structure` → `#work` → `#focus` → `#projects` → `#awards` → `#work-mode` → `#documents` → `#meeting` → `#join`。`main[data-longform]` 上的 `data-active-page` 与 `alethic:chapter` 的 `detail { file, section }` 是当前章节的联动约定。`section` 对应可书签的真实 DOM ID，`file` 用来定位相关内容与图形。滚动更新选中态，地址栏保留用户实际访问的深链接。

## 2. 跟做一幕和一个详情页

### 增一幕

下面的 `#method-notes` 是演练用 ID。可以用自己的主题替换。

1. 在 `topics` 加入一条主题记录，填文件名 `method-notes.html`、片段 `method-notes`、双语标题、导语、主操作与目标。先写读者在本幕要理解的一句话，再写能证明它的一条资料或一个可读对象。
2. 给 `renderTopic(lang, section)` 接入该幕内容。沿用 `renderStory()` 生成的 `.story-screen`、`data-scene-page`、`aria-labelledby` 和标题 ID。自定义幕参照 `renderLab()` 保持同样的外层契约。首幕使用 `h1`，一般新增幕使用 `h2` 和顺序合理的小标题。
3. 如需从页眉进入，将该幕加入合适的栏目组，在 `siteNavigation` 填同一个 `section`。核对首页菜单生成 `#method-notes`，内页生成 `/#method-notes`，英文内页是 `/en/#method-notes`。简单子主题也可以只从相邻正文链接进入。
4. 给本幕分配一个可解释的图形，在 `page-scene.mjs` 检查 `sceneKind()` 对应的主题和 `sceneStrokes()`。按下文校正净区与定位。若这个主题另有需要长期直达的详情，参照会议页使用独立内容与 URL，并显式处理 `oldTopic()` 的兼容规则。
5. 预览中英文直达、栏目跳转、正反滚动。确认当前章、所属栏目、可见标题和画面一致。再从相邻两幕进入和退出，在 320 px 测一次长标题和最长行，在关闭动效的模式确认信息和入口完整。新章要加入相应自动化的章节顺序或入口清单。

交接时用内存夹具跑过 `renderStory()` 的扩展点。中英文都能生成新幕，章节 ID 各出现一次，且关联对应标题。练习时沿用这一检查，再通过实际浏览器验证菜单、锚点和场景。

### 增详情页

以一个公开方法记录为例，在 `editorialPages` 注册 `methods-field-notes.html`，填写双语 `title`、`intro` 和 `render(lang)`。在 `page-template.mjs` 的 `detailActions` 配置可信的主操作，例如 `#method`，正文提供真实的同名 ID。这个文件走普通详情页分支。若选用 FLUED 系列页型，核对 `fluedPages`、页头家族高亮和 `entry.mjs` 的 `flued-ui.mjs` 挂载范围。

从相关幕提供带明确目的的链接，例如「阅读方法记录」，详情给读者一条回到相关章节的路径。使用中文根路径形式填写同域公开链接，由 `build.mjs` 生成英语对应地址。账户、招新和站外资源使用实际服务地址。检查 `/methods-field-notes.html`、`/en/methods-field-notes.html`、直接载入 `#method`、两向换语言以及返回原入口的页面与焦点。把新增的公开路由交给维护者纳入上线检查。

### 旧入口的验证方式

首页主题曾有独立文件。现有九个兼容主题文件会按 `oldTopic()` 回到首页对应幕，会议流程页保留独立地址。兼容测试同时打开旧 URL 和新入口，例如 `/research.html#direction-agent`、`/en/research.html#direction-agent`，以及 `/awards.html#item-2` 对应的 `/#awards-item-2`。验证查询串、字符编码、选中记录和顶栏下的实际落点。公开锚点是外部资料可引用的地址，改名时记录新旧映射并补回归。技术文章含中文片段，测试用解码后的 ID 匹配，并保留浏览器编码后的完整 URL 作为证据。

## 3. 字格、内容净区和组件

### 从资料关系选择图形

| 设计对象 | 可复用的关系 |
| --- | --- |
| 实验室首幕 | 采样、建模、验证、交付四个状态驱动同一幅稳定尺寸的图，选择和状态说明一起更新。可从 `lab-workbench.mjs`、`lab-engraving.mjs` 和 `lab-edition.css` 跟做。 |
| 组织架构 | 从实际控件和标签测量连线端点。开放参与通向社区，同步直招并行连到社团和实验室。判断线是否准确接到文字端口。源码见 `org-wires.mjs`。 |
| 方向与项目 | 研究方向切换实际图形结构，例如分段、取景框或反馈环。FLUED 的刻度依据样本偏移、分段数或实验记录，图例保留单位和来源。 |
| 竞赛和长文 | 竞赛的奖章、队员、导师、编号与 PDF 使用同一记录，桌面预览及触屏选择都核对落点。文章的目录、正文和控制区保留完整阅读底板，背景只绘于有空间的外侧。 |

先标出标题、正文、表格、图例、控制和焦点外沿。长首页的 `.story-intro`、`.story-content` 等框进入净区计算，补充容器可标 `[data-scene-quiet]`。给重要图形留独立空白，有明确位置时可用 `[data-scene-art]` 提供候选区域。图形锚点以章节为参照，往返滚动时投影到同一网格。检查字体加载、切换选项、目录展开及跨断点后的布局，确认文字和控件区域里的 Canvas 像素仍为空。无画布、减弱动效或留白不足时，正文、单位、来源和操作仍由 HTML 提供。

官网字格延续原始品牌的工程细线、边界和定位符号。`+` 用于接点，`|` 可表示真实切分，方括号标记选区。长文与表单使用系统无衬线，等宽只用于字符图、数值、坐标和短标记。共享纸面为 `min(91vw, 1520px)`，基础节距 8 px。12 列到 4 列是排版起点，章节以实测可读区域为准。开场保持纯净，账户、组织资源和偏好进入正文后可用。

### 本轮统一组件色与动作节奏

本轮新增 `src/design-system.css`，并在 `build.mjs` 中进入合并样式。新增组件从语义用途取值。颜色和节奏的具体选择器、局部时长、断点与图形参数查看相应源码。

| 用途 | 对应变量与验收 |
| --- | --- |
| 页面、面板、正文 | `--paper`、`--surface`、`--ink`、`--muted` 在 `system.css` 定义浅深主题。`--line` 负责普通分隔，`--strong-line` 用于重要边界。换任一底色都复测文字与状态。 |
| 主操作、当前项、焦点 | `--ui-accent`、`--ui-text`、`--ui-secondary`、`--ui-selected`、`--ui-focus` 统一角色。主操作可用强调色实底，普通内容链接用下划线，当前项加定位线与语义状态，焦点保留可见轮廓。 |
| 按压、进场和退出 | `--ui-press` 125 ms、`--ui-enter` 220 ms、`--ui-leave` 155 ms，以及 `--ui-ease` 是共享默认令牌。抽屉有专门的进退节奏，悬停意图延时也独立。为交互写验收时以实际采用的 CSS 和 JS 为准。 |
| 测量图和数据系列 | 刻度、奖章和数据系列沿用各图编码。交互色、数据含义、警告与错误分别有可读标签。 |

## 4. 交互、导航与状态

- **先确定动作的语义。** 去另一节或资源用真实链接，局部执行用原生按钮。保留修饰键开新标签、复制链接和浏览器前进后退。可展开区关联触发器与内容。选中、聚焦、悬停、按下、禁用分别可辨，并选用适合控件的 `aria-current`、`aria-pressed`、`aria-selected` 或 `aria-expanded`。
- **让反馈对应于操作结果。** 同一个选择同时驱动控件、图形与记录。切换中途再切一次，检查最终内容与最后一次输入一致。加载与异常要有可读状态。恢复系统主题后，系统色彩偏好变化应更新显示。换语言应保留当前幕或可用的细分锚点。
- **顶栏与偏好分别走查。** 桌面四组顶栏支持鼠标延时展开、跨间隙进入、离开与中途折返。手机用点按，页面滚开时收起主菜单。偏好在桌面页边、手机排在正文之前的正常流里。开合期间检查触点、Tab 顺序和退出的视觉中间帧，Esc 后核对触发器的焦点。鼠标或触摸激活正文控件时记录 `scrollY`。真实 Tab 遇吸顶栏遮挡时才补最小滚动，锚点跳转中保持单一驱动。
- **把移动与目标联系起来。** 页内锚点由滚动到达和可见标题共同确认，顶栏偏移、滚动打断、快速改目标以及历史返回都要验证。跨页转场使用原生链接与历史。中途关闭页面、改用 Tab、启用减弱动效时都要能到达或恢复实际阅读位置。
- **保留原站指针反馈和原生输入。** `site-cursor.mjs` 与 `site-cursor.css` 延续原站随动的点和圆环。支持悬停的精细指针才启用，触摸、编辑控件、失焦、捏合缩放和减弱动效时走原生反馈。验证 `document.elementFromPoint()` 命中真实控件，再检查点和圆环的视觉反馈。

## 5. 全站审查和发布记录

用 Node 22 或以上版本及 Git，在官网工程根目录运行。录屏或正式验收时，使用同一份构建产物和固定预览端口。不同实验可使用独立工作副本及报告目录。

```powershell
npm test
npm run build
node scripts/verify-contract.mjs
npm run preview
```

预览启动后另开终端执行浏览器检查。默认预览为 `http://127.0.0.1:14118`。`ALETHIC_QA_ORIGIN` 可指定隔离预览或获准的预发 origin。浏览器驱动与 Edge 路径查看 `scripts/browser-qa.mjs` 的 `ALETHIC_PUPPETEER`、`ALETHIC_BROWSER`。`--measure` 写测量报告。`--ready` 同时采集截图和录屏，按脚本要求提供 FFmpeg。

```powershell
node scripts/lab-qa.mjs --measure
node scripts/reading-qa.mjs --measure
```

可用 `ALETHIC_LAB_CHECKS` 和 `ALETHIC_READING_CHECKS` 按名称筛选，比如 `^(menus|drawer|article-reading)-`。指定 `ALETHIC_LAB_OUTPUT`、`ALETHIC_READING_OUTPUT` 以保留历史报告。全文浏览可复跑 `node scripts/scroll-story-qa.mjs --measure`。

| 审查对象 | 看什么，怎么留证据 |
| --- | --- |
| 路由和双语 | 枚举中英首页、各独立页、兼容别名和 404。记录首个 HTTP 状态、最终 URL、`lang`、落点、当前项、资源 MIME，以及查询串和旧锚点。静态合约对比固定原站提交、公开 ID、四份 FLUED JSON 和三组证书。 |
| 静帧、净区和图形 | 至少检查 1852、1440、390、320 px，补中英文最长文案、明暗、减弱动效及放大阅读。截图应看得见主要任务和焦点。技术文章、项目目录和切分尺同时检查 Canvas 内外像素。 |
| 任务与输入 | 正反滚动、触屏、全键盘、Esc、快速连点、返回、可中断跳转与偏好保持。复验第一幕四态、研究七方向、竞赛三队证书、组织连线、会议四阶段、FLUED 代表工具以及加入入口。记录动效中间帧、触点命中和滚动位置。 |
| 问题记录 | 写发布号、页面/语言/宽度/主题、操作步骤、预期、观察值、影响和复测结果。用 CSS 的 `/assets/<构建号>/drawing.css`、版本记录和报告对应证据。 |

## 7. 上线条件

1. **静态与边缘路由。** 同一份产物通过合约和浏览器矩阵。验证根目录、`/en/`、公开 `.html`、旧地址首跳、查询串和带片段的最终落点。未知地址响应 `404`。录屏、抽查和报告记录相同的构建身份。
2. **同域业务。** 有可用的预发服务及授权测试账号。按代理配置验证 `/login`、`/account`、`/recruitment/`、`/admin/recruitment` 和真实 `auth/me`。测匿名、有效与过期会话、登出、报名、上传下载、账号权限、管理和机试。匿名与失败时账号入口仍可去登录。动态及身份响应遵守 `no-store`，只读热备按既有回退条件处理，写入保持主源语义。静态预览的业务 503 用于标明服务未接入。
3. **内容、缓存与回退。** 由内容维护者确认获奖名单、证书、治理和成员资料，再由研究维护者确认待发布的数据快照。版本化静态资源与稳定路径分别核对缓存策略，实际响应以宿主为准。留存上一可用产物、对应的代理与路由配置，以及预发和生产抽查记录。 [部署与业务验收](部署与业务验收.md) · [原站入口与内容核对](原站入口与内容核对.md)
