# Alethic 官网部署与业务验收

## 构建和基线

用 Node 22 或更高版本及 Git。在重写工程根目录执行以下命令。CI 中用 `--source` 指向含基线提交的原站 Git 检出目录。脚本默认读取相邻的 `Alethic-官网迁移候选`，通过 Git 对象读取固定提交，候选工作树里的未提交改动不会改变验证结果。`--ref` 可指定维护者确认的替代基线提交。

```powershell
npm run build
node scripts/verify-contract.mjs
npm run preview
```

```powershell
node scripts/verify-contract.mjs --dist './dist' --source '..' --ref c9128367e3081b5c0ccdef8dd92af806de7746b5
```

脚本检查 8 个旧公开页面和新增会议页、57 个旧公开锚点、4 份 FLUED JSON 的实际内容、3 组证书 PDF 和预览图的文件内容，以及静态站内引用、三个同域业务入口和部署文件。`/` 与 `/index.html` 使用同一个 `index.html`，由预发 HTTP 验证两个地址的响应。旧页面中只供样式或无障碍标注使用的内部 ID 可重写。脚本遇到失败返回非零，输出文件、路径和锚点。它只检查文件和 Git 对象，浏览器行为、HTTP 和真实业务按以下清单验收。

固定基线为 `CUMT-Alethic-Insight-Lab/website@c9128367e3081b5c0ccdef8dd92af806de7746b5`。迁移清单记录了线上三份 FLUED JSON 与该提交字节不同。上线前由研究维护者核对两边实际内容及来源，确认应发布的数据快照。成员名录及竞赛、治理、项目入口由内容维护者确认。 [原站基线](https://github.com/CUMT-Alethic-Insight-Lab/website/tree/c9128367e3081b5c0ccdef8dd92af806de7746b5) · 迁移清单

## 域名和路由

静态站按域名根目录部署。先匹配服务路径，再尝试静态文件。`/`、`/index.html`、`/people.html`、`/insights-memory-hierarchy.html`、`/flued.html`、`/flued-architecture.html`、`/flued-demo.html`、`/flued-evidence.html`、`/flued-experiments.html` 和 `/meeting.html` 均应直接返回目标页面。英文页面使用同域 `/en/`。未知路径返回 404，可渲染 `404.html`。预览遇到业务路径返回 503，标明需要预发环境。

| 公网路径 | 托管层行为 |
| --- | --- |
| `/recruitment` | `301` 到 `/recruitment/`，附带查询串 |
| `/recruitment/admin` | `301` 到 `/admin/recruitment`，附带查询串 |
| `/admin/recruitment/` | `301` 到 `/admin/recruitment`，附带查询串 |
| `/login` | 内部同域代理到招新主源的 `/login`。原提交没有该别名，维护者需确认生产映射及回跳路径 |
| `/account` | 内部同域代理到招新主源的 `/account`。原提交没有该别名，维护者需确认生产映射及匿名回跳 |
| `/admin/recruitment` | 内部同域代理到招新主源的 `/admin` |
| `/recruitment/` | 内部同域代理到招新主源的 `/` |
| `/recruitment/<剩余路径>` | 去掉 `/recruitment` 前缀后内部转发。覆盖 `/recruitment/login`、`/recruitment/apply/<届次>`、`/recruitment/api/**` 及招新静态资源和上传、下载路径 |

内部转发后，浏览器仍使用官网域名。保留 HTTP 方法、请求体、查询串、会话 Cookie 和下载所需的 Range 请求。把上游 `Location` 和 `Set-Cookie` 核对到公开路径，验证重定向保持同源，Cookie 的 `Path`、`Domain`、`Secure` 和登出删除行为能同时覆盖短路径及 `/recruitment/api/auth/**`。预发招新服务需配置和允许对应的公开前缀与管理员路径。登录、个人中心、管理及 API 响应使用 `no-store`，在 CDN 上绕过缓存。响应体确认来自接口，避免把 HTML 错认作 JSON。主源不可达或命中既有的 502、503、504、520–530 回落条件时，仅 GET 和 HEAD 可走只读热备，写操作应返回 503。登录成功、报名和机试的写入验证只使用独立的预发数据、测试批次和授权账号。

### nginx 与现有部署

原仓发布手册描述了 nginx 加 Cloudflare Tunnel 的生产路径，按维护方当前配置确认。以相同拓扑部署时，宿主继续使用现有招新代理并补齐上述 URL，`root` 指向新静态产物。`_headers` 与 `_redirects` 是 Pages 配置文件，nginx 需分别应用相同的缓存、跳转和真实 404 行为。设置 HTML、JSON、JS 模块（`.mjs`）、CSS、PDF 与 PNG 的 MIME。预发需准备与生产隔离的招新主源、测试热备、TLS 和域名，确认上传大小及超时、HTTP Range 和考试套件的同域地址。 [原站发布说明](https://github.com/CUMT-Alethic-Insight-Lab/website/blob/c9128367e3081b5c0ccdef8dd92af806de7746b5/README.md) · [代理和部署预案](https://github.com/CUMT-Alethic-Insight-Lab/website/blob/c9128367e3081b5c0ccdef8dd92af806de7746b5/docs/cf-pages-migration.md)

### Cloudflare Pages 所需部署适配

以 `dist/` 为静态根。部署侧须提供 `/login`、`/account`、`/recruitment`、`/recruitment/*`、`/admin/recruitment` 与 `/admin/recruitment/` 的实际反代路由，接收前述方法和请求体。在项目根 `functions/` 实现时，可按 `functions/login.js`、`functions/account.js`、`functions/recruitment/[[path]].js` 和 `functions/admin/recruitment.js` 组织，并确认两个裸路径与尾斜杠都进入预定处理逻辑。基线中的公共转发函数可供维护者对照。部署绑定 `LAB_ORIGIN`、`STANDBY_ORIGIN`，回源启用 Cloudflare Access 时在服务端设置 `CF_ACCESS_CLIENT_ID` 和 `CF_ACCESS_CLIENT_SECRET`。预发绑定应指向独立测试上游。这些适配由宿主项目提供，本次静态产物内只交付三条 `_redirects` 和静态 `_headers`。

由 Function 接管的地址需要在 Function 自身处理 301、查询串和响应头。Pages 的默认 HTML 规范化可能把 `/index.html` 和其他 `.html` 地址重定向到无后缀路径。若预发需保持原来的直接 200，应在边缘用精确路由实现相同文件响应，并实测首跳。未具备该适配时，沿用能直接服务原 `.html` 路由的现有宿主。 [Pages 重定向](https://developers.cloudflare.com/pages/configuration/redirects/) · [响应头](https://developers.cloudflare.com/pages/configuration/headers/) · [HTML 和 404 行为](https://developers.cloudflare.com/pages/configuration/serving-pages/)

## 预发验收与回退

预发状态待验。当前分工未获得预发 origin、测试届次或授权账号。记录预发域名、构建版本、数据提交、时间、执行人与每项结果。`curl.exe -sS -D - -o NUL` 可读取首个 GET 响应，不附加 `-L`。用阶段记录核对如下任务。

| 任务 | 通过标准 |
| --- | --- |
| 公开旧地址 | 逐个直开并刷新上表公开路径。核对 200、实际页面标题、`.mjs` MIME 和 404。分别从 `/#direction-llm`、`/index.html#documents`、`/people.html#join`、文章百分号编码的 `#架构` 及 `/flued-demo.html?autorun=sample#input` 进入，确认滚动、焦点和返回行为 |
| 业务入口和匿名状态 | 只读 GET 检查三条 301 及查询串、三个入口页面与旧登录别名、管理入口、`/recruitment/api/health`、`/recruitment/api/auth/me`、`/recruitment/api/campaigns/latest-open`。验证匿名账号返回、未开届次的真实提示和动态响应禁止缓存 |
| 授权业务 | 用预发普通账号及管理员验证错误登录、成功登录、资料读取、会话过期、登出和后台权限。完成一条测试报名及续填，核对进度回流。用测试安装包验证机试登录、提交、上传及下载。模拟主源失效时核对只读回落和写入 503 |
| 公开研究与内容 | 选择样本 A 并运行，确认预录标注、输入、分段、补全和耗时。检查总览切分、证据页组别和指标、实验图谱搜索和筛选。本机实时推理需要研究维护者的独立服务。核对 3 份 PDF、证书图、名录、治理文档、文章目录和引用链接 |
| 品牌交互与可访问性 | 分别在 1440、390 和 320 像素检查首屏可停留、鼠标或滚动进入正文、触屏与键盘、站内和浏览器返回、可见焦点、深浅主题与中英文跨页记忆。开减少动效后复测主路径。会议页标明流程演示，正式投稿与评审在身份、流程和后端确定后独立验收 |
| 发布与回退 | 新版独立版本部署并保留前一版，先在预发切换、回退及复测静态、招新与 FLUED。保留仍被旧 HTML 引用的指纹 JS/CSS，由托管层按原 URL 提供。原公开 `/mark.svg` 和 `/fonts/*.woff2` 使用托管层原地址兼容映射。用 `git ls-tree -r --name-only <原站提交> -- public/assets public/fonts public/mark.svg` 清点旧公开资源地址，并对照生产发布资产清单补齐。记录兼容资产的来源和保留期。核对缓存中的 HTML 仍可载入对应版本的资产，再切换生产入口 |

`/assets/*` 先使用短缓存，确认某条 URL 随内容变化后再对该版本路径启用长期不可变缓存。现有证书与字体使用 7 天缓存。稳定 URL 修订时同步核对失效策略。对账号和招新使用单独的动态响应策略。当前阶段没有接入真实预发或生产业务操作。

## 本工作分支采用的 skill

| Skill | 怎样体现 |
| --- | --- |
| `test-driven-development` | 先写合约检查并用旧候选构建验证失败路径。旧 FLUED 脚本引用和宽泛的不可变缓存规则均被识别。旧候选页面用于回归对照 |
